## 1. 一手六要素 → 本库落地映射

| # | Doto 六要素（`book-summary.md:58-65`） | 本库落地 | 门禁档位 |
|---|---|---|---|
| 1 | **标题** — 一句完整的命题句 | 文件名（短可读名）+ 页面 H1（声明式断言） | 硬 gate 查「有 H1」；是否命题句 → 诊断 D3 |
| 2 | **单一想法** — 一卡一想法、用自己的话 | `## 单一想法` 段 | 段存在 → 硬 gate；是否真原子 → 诊断 D1/D2 |
| 3 | **链接** — 带上下文的连接 | `## 链接` 段，每条 `[[页名]] — 为什么链` | 目标存在 / 禁堆砌 → 硬 gate G1/G2；理由是否成立 → 诊断 D4 |
| 4 | **引用来源** | `origin::` property + `## 出处与引文` 段 | 段/property 存在 → 硬 gate；是否填实 → 诊断 D5 |
| 5 | **使用记录** — 在哪篇文章里用过 | **Logseq 反链自动形成**：Structure Note / 草稿里 `[[ ]]` 引用本卡即可 | 诊断 D12 只报反链数，**不要求手填字段** |

> 本库 `## 使用记录` 段是**说明位**，不是待填字段；不要为了凑六要素往里编内容。

## 2. 本库与书的四处差异（用户裁决优先）

| 差异 | 书里 | 本库 | 理由 |
|---|---|---|---|
| **ID 留空** | 必填，创建时分配 | `folgezettel::` 留空，用户手工填 | 用户裁决；做成硬 gate 会逼 Agent 乱编号。**不改** |
| **本地扩展段** | 无 | `## 支撑材料` / `## 拆分候选` / `## 待建链接` | 用户偏好写足推理、机制、示例与演化记录；**不计入六要素**，不得拿来做合格评分 |
| **来源写法** | 正文末尾 `来源：` 块 | Logseq `origin::` + `## 出处与引文` | 库统一用 properties，不用 YAML / 不用尾注块 |
| **链接语法** | Obsidian `[[ ]]` / Capacities `[](url)` | Logseq `[[页名]]`，目标逐字等于文件名 | 平台驱动见 `platforms/logseq.md` |

## 3. 落点、命名与 properties

- 目录：`pages/原子笔记/`（硬 gate G4 校验位置）
- 文件名：简体中文短可读名，无空格无特殊符号，建议 ≤20 字；可与 H1 不同（H1 是命题句，文件名是短名）
- 页首 properties（Logseq 格式，**不用 YAML frontmatter**）：

```
type:: 原子笔记
folgezettel::
created:: YYYY-MM-DD
origin:: <现场来源：与谁、何时、由什么引出>
tags:: <沿用 SCHEMA 主题分类法；无合适领域可留空，勿自造>
claim_type:: <事实 | 推理 | 类比 | 判断 | 决策>
verified:: <true | false | 推理 | 类比 | 待查>
```

`type` / `folgezettel` / `created` 为硬 gate 必检；`folgezettel::` 后留空是**正常状态**。

**两个可选字段（2026-11-11 AI 时代修订，见 `PRINCIPLES.md` 第 5 节）**：
- `claim_type::` 标这条主张是什么类型的断言；`verified::` 标证据到哪一步。
- ⚠️ **都不是必填、都不进硬 gate**。`doto_audit.py` 的 D16 只会在含机制/数值断言却空缺时提示「区分事实与推理」；做成必填会逼 Agent 编标注。
- `verified::` **复用 `SCHEMA.md:37` 实体页已有的同名 property**，`true`（有实据）/ `false`（AI 生成待核）含义不变；主笔记可填更细的值（`推理` / `类比` / `待查`）。不要另起一个同义字段。
- 判断立场（`stance`：我同意什么、反对什么、据此打算做什么）写在 `## 单一想法` 正文里，**不做成 property**，理由同上。

## 4. 段落骨架（`zettelgate new` 生成）

| 段落 | 性质 | 说明 |
|---|---|---|
| `## 单一想法` | **六要素 2** | 一个主张，用自己的话写成完整句子，不摘抄；写明判断立场（同意/反对/据此做什么），不另建 `stance::` 字段 |
| `## 支撑材料` | 本地扩展 | 机制 / 示例 / 反例 / 边界条件，写足推理不压成口号 |
| `## 出处与引文` | **六要素 4** | 现场来源 + 文献引文（注明译本差异）+ ⚠️ 未核实内容 |
| `## 链接` | **六要素 3** | 每条写明「为什么链」，注明连接类型（延伸/对比/因果/举例/质疑/跨域） |
| `## 待建链接` | 本地扩展 | 候选方向写**平文**，注明「候选，建卡后再改 wikilink」 |
| `## 使用记录` | **六要素 5** | 说明「靠反链自动形成」，不填内容 |
| `## 拆分候选` | 本地扩展 | 卡偏大时列出可独立成卡的想法，兼作演化记录 |

`单一想法` / `支撑材料` / `出处与引文` / `链接` 四段为硬 gate 必检（G5，库规约）。

## 5. 链接纪律（Ch.4，`doto-connect_SKILL.md`）

- 每条链接**必须带上下文**：`[[页名]] — 为什么链`，说明属于哪种连接类型
- ❌ 禁止链接堆砌：连着三个裸 `[[ ]]` 无任何说明 → 硬 gate G2 直接 FAIL
- **质量比数量重要**：一个恰到好处的连接胜过十个随意连的；单卡 >4 出链会进诊断 D7
- **暂时没有连接是正常的**：不要为了连接而连接（`doto-connect_SKILL.md:160`）；新卡孤岛不报问题
- 只有**已存在的页**才能写成 `[[页名]]`，且逐字等于文件名；未建的写平文放 `## 待建链接`
- 不手写反向链接 —— Logseq 自动计算，反链即使用记录
- 即兴连接允许：拿不准的关系也可以连，但**必须写出为什么**

## 6. 诚实标注（本库约定）

AI 推理出的机制、类比、温度阈值等，未查一手文献一律加 ⚠️ 并写明「推理类比，待核」；不要把类比当成核实过的事实。

2026-11-11 补充：正文里的 ⚠️ 是**给人看的留痕**，`claim_type::` / `verified::` 是**给 Agent 看的同一件事**。两者都算留痕，不强求同时具备；D16 遇到「已有 ⚠️ 但字段空缺」时只提示「可升级为可机读」，不算不合格。

## 7. 写入流程与门禁

```
zettelgate new "声明式标题"        # 生成骨架（不会自动登记）
→ 填六要素，写完自查 PRINCIPLES.md 的诊断项
→ zettelgate add <文件> --summary "一句话摘要"   # 幂等登记 index/log + 硬 gate lint
→ zettelgate audit                 # 可选：主动体检，只出报告不改文件
```

- `add` 后 **lint 必须 0 断链**才算完成；`audit` 恒为 0，不阻断写入
- **Folgezettel ID 留空，agent 不自动编号**
- 拆分卡片：每张独立走 `add`；母卡的「待建链接」升级为 wikilink 时逐条补「为什么链」
- 写作产出（Structure Note / CLOG）不属于主笔记，见 `WRITING.md`；这些页用 `zettelgate register` 登记
