> 本文件只写**在这个库里怎么落**：放哪、什么 type、走哪个命令、什么时机才建。

**最高原则**：`A zettelkasten will not tell you what to write.`（`book-summary.md:90`）
库负责捕捉 → 连接 → 组织；起草、编辑、发布的每一个字由人写。**ZK 不替你选题，也不替你写。**

## 1. 三种组织/管理页（别混）

| | Hub Note 枢纽笔记 | Structure Note 结构笔记 | CLOG 创意日志 |
|---|---|---|---|
| 类比 | 高速公路交汇处（地图） | 建筑蓝图（大纲） | 工作台上的便签 |
| 回答 | 「这个主题有哪些想法，从哪进」 | 「这篇文章怎么论证」 | 「下次打开从哪继续」 |
| 内容 | 分支起点的 `[[ ]]` + 一句话 | 按论点排列的 `[[ ]]` + 过渡 + 论证缺口 | 本次完成 / 待处理 / 心得 / 下次开始建议 |
| 创建时机 | 同主题主笔记 **≥8 条** 且觉得散 | 用户明确说「我想写…」，且集群 **≥3 条** | **每次写作会话结束** |
| 出处 | `doto-connect_SKILL.md:91-97` | `doto-connect_SKILL.md:119-141` | `doto-write_SKILL.md:160-186` |

⚠️ **受控混乱**（Ch.6）：分区标题只能在想法积累后**后补**，不能预先设定。
所以本库**不预建空目录、不预先给主题分区**；`vault-config.json` 里登记 type 只是让门禁认识它，不代表现在就要用。

## 2. Logseq 落地

| 类型 | `type::` | 目录（有内容时才建） | index 分节 |
|---|---|---|---|
| 枢纽笔记 | `枢纽笔记` | `pages/枢纽笔记/` | `## 结构笔记` |
| 结构笔记 | `结构笔记` | `pages/结构笔记/` | `## 结构笔记` |
| CLOG | `CLOG` | `pages/CLOG/` | `## 结构笔记` |

- 元数据一律 Logseq properties（`key:: value`），不用 YAML frontmatter
- 链接用 `[[页名]]`，目标必须已存在；候选方向写平文
- 登记统一走 **`zettelgate register <已在库内的.md> --summary "一句话"`**（幂等维护 index/log + lint）
  —— 不用 `add`，因为 `add` 是主笔记专属，会硬检 `type:: 原子笔记` 与四段骨架
- 文件名建议带日期/项目：如 `2026-11-11-LGMTv3.md`（CLOG）、`LGMT模型与公理思维.md`（Structure）

### 结构笔记模板

```
type:: 结构笔记
created:: YYYY-MM-DD
project:: <文章/书稿名>
status:: 草稿 | 论证中 | 已发布

# <文章标题> — 结构笔记

## 核心论点
<一句话想论证什么>

## 论点 1：<子标题>
- [[主笔记页名]] — 在论证中起什么作用
- [[主笔记页名]] — 补充/反驳视角

## 论证缺口
- <缺案例 / 缺数据 / 缺要回应的反驳>   ← 每个缺口都是下一次建卡的方向

## 写作顺序建议
1. <先写哪段，为什么>
```

## 3. 渐进式发布（Ch.8）

```
主笔记集群 → 短内容 → 博客 → 长文章 → 书籍
     ↑                              │
     └──── 反馈 + 新想法 ←──────────┘
```

| 形式 | 量级 | 来源 | 目的 |
|---|---|---|---|
| 短内容（推文/朋友圈） | 50–300 字 | 单条主笔记 | 快速测试想法有无共鸣 |
| 博客 | 800–2000 字 | 一个主题的集群 | 连贯论述 |
| 长文章 | 3000–8000 字 | 多个 Structure Note | 多论点严谨论证 |
| 书籍 | 50000+ 字 | 多篇长文章整合 | 系统性输出 |

**升级判据**（`doto-write_SKILL.md:42-47`）：
1–3 条 → 短内容投石问路；5+ 条且有 Structure Note → 博客；多个 Structure Note → 长文章；3+ 篇相关长文 → 考虑写书。
另有 **Folgezettel 成熟度信号**：同主题下出现深长 ID 链（如 `4.3a1b`）→ 这条线值得优先写。

## 4. 从笔记到草稿的 8 步（`doto-write_SKILL.md:51-133`）

1. **选题**：找连接密度高的集群，≥3 条起步
2. **建 Structure Note**：用上面的模板，排列论点
3. **审查**：逻辑断裂 / 论据缺失 / 论点重复
4. **补充**：缺口回到 `zettelgate new` 建主笔记；事实性缺口先记参考笔记（见 `INGEST.md`）
5. **起草 —— 重写，不是复制**：把草稿当全新文字写，需要论据时引用笔记观点。Zettel 是原料仓库，不是预制件
6. **编辑**：删减、重组、补过渡
7. **发布**：按形式选渠道
8. **使用记录**：在 Structure Note / 草稿里 `[[ ]]` 引用主笔记 → **Logseq 反链自动形成**
   —— 这就是六要素第 5 项，**不要手填 `used_in`**

> ⚠️ 第 5 步是整个流程最容易塌的地方。把笔记复制粘贴凑成文章是 Doto 点名的最差写法。

## 5. 写作管理（Ch.9）

- **日记 / 收件箱**：临时想法用 `💡 一句话` 快速捕捉，不打断思考流；不要求都转主笔记
- **CLOG**：每次写作会话结束必写「下次开始建议」。Doto 称它是最被低估的工具
- **任务驱动项目管理**（有截止日时）：定义项目 → 头脑风暴任务 → 从 ZK 搜笔记建 Structure Note → **只做今天的任务** → 记 CLOG → 反思
- 搁置不是放弃：Structure Note 的「论证缺口」长期填不上就搁置，笔记不会过期

## 6. 门禁如何覆盖 Part III

| 检查 | 档位 | 出处 |
|---|---|---|
| Structure / Hub / CLOG 的 `type::` 合法性 | 硬 gate G6 | 库规约 |
| 这些页的 `[[ ]]` 目标存在、index 有条目 | 硬 gate G1/G7 | 书 + 库规约 |
| 同主题 ≥8 条主笔记 → 提示建 Hub | 诊断 D10 | Ch.6 |
| ≥3 条集群且要写作 → 提示建 Structure Note | 诊断 D11 | Ch.7 |
| 反链数（使用记录） | 诊断 D12 | Ch.3 |
| `## 论证缺口` 非空 → 下次建卡方向 | 诊断 D15 | Ch.7 |
| CLOG `## 待处理` >5 条 | 诊断 D14 | Ch.9 |

**不做成硬 gate 的**：必须有 CLOG、必须有 Structure Note、必须达到某个字数、必须归入某主题。
理由见 `PRINCIPLES.md:0` —— 可持续性第一，别逼出为填模板而写作。
