# PRINCIPLES.md — 书的原则如何变成门禁

> **本文件是 `lint.py` / `doto_audit.py` 的设计依据。** 改检查项前先改这里，别让代码里悄悄长出没有出处的规则。
> 方法论正文在 `references/doto/`（只读快照，见其 `SOURCE.md`）；本文件只做「原则 → 可校验项 → 档位」的映射。
> 建立于 2026-11-11，用户裁决：**硬 gate + 诊断报告两档**；同日增补第 5 节「AI 时代的分档修订」（只换依据，不动档位）。

---

## 0. 为什么必须分两档

书的第一原则是 **可持续性**：

> "A Zettelkasten succeeds or fails based on sustainability." — `references/doto/book-summary.md:84`

`doto-audit` 三条铁律（`references/doto/methods/doto-audit_SKILL.md:16-22`）：

1. **AI 只诊断，不动手修改**
2. **遇到再处理，不批量重构** —— 批量回去改旧笔记，是让人放弃 ZK 的最快方式
3. **最好的迁移策略是不迁移** —— 现有笔记原样留着，只在恰好遇到它时顺手规范化

推论：**凡是靠语义判断的（原子性、原创性、标题好不好、链接理由成不成立），一律不做 `FAIL`**。
否则 Agent 会为了过门禁而填字段、凑链接、把想法压成模板——那正好毁掉系统。
机器只负责「客观且无争议」的那几项；其余写成报告，交给人或 Agent 在 15 分钟时间盒里挑着处理。

### 进硬 gate 的三个条件（全满足才行）

| 条件 | 说明 |
|---|---|
| ① 可客观判定 | 字符串/正则/文件存在性可判，不需要读懂语义 |
| ② 判错代价低 | 误报时能立刻看懂怎么改，不会逼人改写想法 |
| ③ 书里明确写了「必须/禁止」 | 或属本库工程约定（须显式标注为库规约，不冒充书） |

### 分类（沿用 `doto-audit` 模式 A，只贴标签不动手）

`✅ 保持` / `🔧 小修` / `✂️ 建议拆分` / `📦 降级为参考笔记` / `🗑️ 建议删除`

判定来自 D1–D5 的组合，**D6–D16 只作旁注，不改变分类**。
报告末尾固定提示：先从「小修」入手、一次最多 15 分钟、余下的放回队列、三个月后回头看。

## 4. 明确不做成检查的东西

- ❌ 「必须至少 1 个出链」：书里说至少 1 个，但也说**新笔记暂时没连接是正常的、不要为了连接而连接**（`doto-connect_SKILL.md:160`）。做成硬 gate 必然逼出凑数链接 → 放 D9 正相反。
- ❌ 「必须有 `## 使用记录` 内容」：Doto 靠反链自动形成（`doto-write_SKILL.md:131`），手填字段是误读。
- ❌ 「必须使用主题 tag / 归入某分区」：违反受控混乱、分区标题后补（Ch.6）。
- ❌ 「笔记长度上限 / 句子完整度打分」：语义判断，交给 Agent 读报告时说，不进代码。
- ❌ 批量自动修旧笔记：`doto_audit.py` 无写权限，任何 `--fix` 都不提供。
- ❌ 校验 `claim_type::` / `verified::` 的取值合法性、或把它们设为必填：两个字段是**可选的人类留痕**，做成硬 gate 会逼 Agent 编标注。D16 只诊断。

## 5. AI 时代的分档修订（2026-11-11）

> **本节只改「为什么保留这一项」的依据，不改任何档位、检查逻辑与退出码。**
> 第 2/3 节表格里的「出处」仍是书里的原文依据；本节补的是「今天为什么还要它」。
> ⚠️ 本节是**本库的设计判断**，不是 Doto 书里的结论，不要冒充书；依据边界见 5.4。

### 5.1 变了什么：第一读者换了

| | 卢曼（物理卡片盒） | Doto（前 AI 数字） | 本库现在 |
|---|---|---|---|
| 第一读者 | 未来的自己，靠分支编号与关键词索引在盒子里漫游 | 未来的自己，靠全文检索与反链 | **Agent**：笔记是每次任务要注入的上下文 |
| 主要稀缺 | 找不到、翻不动、改不了、抄不起 | 人的注意力与理解 | **context 预算** + **可追溯的人的判断** |
| 典型崩法 | 卡片太多，翻不动 | 人坚持不下去 | 自动写入大量未经判断的生成物 |

关键机制：**「涌现」需要一个漫游者**。卢曼的意外连接来自人反复顺着编号与链接走，撞见自己忘掉的东西；Agent 只有一次遍历、按字符付费，这条路径不成立，改由模型主动生成候选连接。于是稀缺从「发现连接」移到「**判断哪个连接值得留下来**」。

由此产生两个书里没有的约束：
1. **context 预算**：195 页 / 1000+ 链接不能整包塞进上下文，笔记必须是可切分、可判定相关性的最小单元。
2. **判断留痕**：模型没有跨会话的连续意志，「谁在何时、凭什么下了这个结论」只能由库保存。

### 5.2 依据补注（档位一律不变）

| 项 | 书里原本在补什么 | 今天的依据 | 档位 |
|---|---|---|---|
| **G3 / D6** Folgezettel | 纸卡只能线性排列、没有全文检索，编号＝物理邻接＝廉价的相关性发现；关键词索引只记少量入口，因为全量编目太贵 | 语义检索让「入口」无限廉价，编号**退为可选的人类策展痕迹**。留空手工填仍是用户裁决；做成必填会逼 Agent 乱编号 | 硬 gate（仅格式）/ 诊断，**不变** |
| **G1** 链接目标存在 | 手写地址若指错，链条就断 | 断链在 Agent 侧会变成检索空洞，且模型可能凭空造页名 | 硬 gate，**不变** |
| **G2** 禁链接堆砌 | 链接是唯一关联手段，人工写才存在，堆砌等于没写理由 | Agent 能一次生成 20 条「看似合理」的连接；从防凑数升级为**防合成淤积** | 硬 gate，**不变** |
| **D1** 原子性 | 卡片容量小、不可无损复制，必须拆开才能重组 | 重组成本≈0，但**一卡一主张是最小检索单元、省 context**；理由换了，要求反而更硬 | 诊断，**不变**（语义不可机判） |
| **D2** 原创性 | 抄写昂贵，抄一遍本身就是理解检验 | 摘要生成成本≈0，摘要不再有认知价值；改看「**有没有人的判断留痕**（同意/反对/据此做什么）」 | 诊断，**不变** |
| **D3** 命题句标题 | 话题标签式标题让人日后认不出卡里写了什么 | 命题句是 Agent 判断相关性时唯一可靠的短信号；`index.md` 的一句话摘要同理 | 诊断，**不变** |
| **D4 / D7 / D9** 连接理由与密度 | 理由写下来，关系才存在；质量比数量重要 | 带类型的连接（延伸/对比/因果/质疑）变成**检索基础设施**；同时「暂时无连接是正常的」用来抑制模型凑链 | 诊断，**不变** |
| **D10 / D12** Hub 与反链 | 人翻不动全库，需要手工导航层与手工反链 | Hub 降为 Agent 按需生成的一次性视图，不必沉淀成永久页；反链/使用记录已可自动形成 | 诊断，**不变** |
| **最高原则** 可持续性 | 全靠人力，攒多了就崩 | 崩法变了：纪律对象从「人要不要写」换成「**AI 准不准写**」；两档门禁正是防「为过门禁而填字段」 | 不进门禁，**不变** |

### 5.3 「不批量重构」反而要加硬

Agent 记忆系统（如 A-MEM 一类 Zettelkasten-inspired 方案）确实能做到「新记忆入库时自动改写旧记忆」——这是卢曼物理上做不到的事。但那只适用于**机器记忆层**；本库的主笔记是「某人在某时某刻的判断」，被自动覆盖后，判断的来路和演化就没了。

所以 `doto-audit` 的「只诊断不动手 / 不批量重构 / 15 分钟时间盒」在 AI 时代从**书里的建议**升级为**库规约**：

- `doto_audit.py` 只读、无 `--fix`、退出码恒 0；
- **Agent 不得依据诊断报告自动重写既有主笔记**，任何改动须用户逐条确认；
- 矛盾仍按 `SCHEMA.md`「矛盾不覆盖」：双方并列 + 日期 + 来源；
- `supersedes::` 一类的「取代关系」留到 P1 再定，本轮不引入。

### 5.4 诚实边界

- 卢曼机制（约 9 万卡、`1→1a→1a1` 分支编号、关键词索引只记入口、1981《与卡片盒交流》）核自**二手资料**，未读德文原文。
- A-MEM（NeurIPS 2025）、Hindsight 的「证据与推断分开存」、context engineering 等说法来自**行业文章**，未读一手论文；上表是设计判断，不是核实过的结论。
- 本节**没有**新增硬 gate、没有改变退出码、没有批量改写任何历史笔记。

## 6. 入口

```
zettelgate lint    # 硬 gate：失败退出码 1，可被 CI/cron 用
zettelgate audit   # 诊断报告：恒为 0，给人看
```

`zettelgate add` 写后自动跑 **lint**，不跑 audit（避免把诊断噪音塞进每次写入）。
audit 是**主动体检**动作，按 `doto-audit` 模式 A，由用户发起或定期手动跑。
